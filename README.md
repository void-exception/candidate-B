# Отчёт по договорам и работам

Формирование отчёта по выплатам и остаткам задолженности по договорам и работам с учётом исторических дат, статусов работ, целевых и общих платежей.

## Требования к окружению

- Python 3.10+
- Стандартная библиотека Python (`decimal`, `csv`, `datetime`, `subprocess`, `pathlib`) — внешние зависимости не требуются.

## Инструкция по запуску

### 1. Формирование отчёта на конкретную дату (например, 10 ноября 2026 года)

```bash
python3 report.py 2026-11-10
```

### 2. Формирование отчёта на текущую дату

```bash
python3 report.py
```

При запуске отчёт выводится в консоль и автоматически сохраняется в CSV-файл `report.csv`.

### 3. Запуск автоматических тестов

В проекте предусмотрены два набора тестов:

```bash
# Основные модульные тесты финансовой логики
python3 test_report.py

# Тесты граничных случаев и проверок соответствия требованиям
python3 test_edge_cases.py
```

Или запуск всех тестов одной командой:
```bash
python3 test_report.py && python3 test_edge_cases.py
```

## Входные данные (`data/`)

Программа считывает данные из CSV-файлов в директории `data/`:
- `contracts.csv` — реестр договоров и сумма контрактов.
- `works.csv` — спецификация работ по договорам (с датами завершения `completed_at` и отмены `cancelled_at`).
- `payments.csv` — реестр платежей (с датами оплаты `paid_at`, возврата `refunded_at` и статусами `paid`, `queued`, `refunded`).

## Правила расчёта

1. **Точность**: Все денежные показатели рассчитываются строго с использованием типа `Decimal`.
2. **Историчность**: Статусы работ (`done`, `planned`, `cancelled`) и учёт платежей определяются строго на указанную дату отчёта (`report_date`).
3. **Платежи**:
   - `paid` учитываются только если `paid_at <= report_date`.
   - `queued` игнорируются.
   - `refunded` учитываются как выплата до даты возврата (`report_date < refunded_at`), после даты возврата игнорируются.
4. **Привязка платежей**:
   - Платежи с `work_id` относятся напрямую к указанной работе.
   - Платежи без `work_id` распределяются пропорционально стоимости всех неотменённых (действующих) работ договора (включая `planned`).
5. **Отменённые работы**: Исключаются из распределения авансов, их остаток показывается равным 0, а стоимость выделяется отдельной строкой в итогах договора.
6. **Переплаты**: Не скрываются, отображаются в отдельном столбце `Переплата` (в консоли и в CSV).

- `report.py` — основной скрипт формирования отчёта.

- `test_report.py` — модульные тесты.
- `test_edge_cases.py` — тесты граничных случаев и контрольных данных.
- `DECISIONS.md` — реестр принятых архитектурных и финансово-логических решений.
- `NOTE_TO_ACCOUNTANT.md` — пояснительная записка для главного бухгалтера.
